# Player Partner

一个给 Minecraft **1.21.1 / NeoForge** 准备的小模组：添加一个只有玩家一半体型的伙伴。它是**真正的玩家实体**——会出现在 TAB 列表、`/list`、玩家计数里，因此可以和其他“把玩家当玩家”的模组联动。

## 功能

- **真正的玩家**：伙伴是服务端注册的 `ServerPlayer`，和普通玩家一样出现在玩家列表里；默认伙伴显示名为 **PlayerPartner**（没有空格，方便命令选中）。
- **一半体型**：通过原版 `generic.scale` 属性设为 0.5（会同步给客户端），碰撞箱 0.3 × 0.9 格、视线高度 0.81 格，模型也由原版渲染器自动缩放 0.5 倍——服务端与客户端看到的大小始终一致。
- **正版皮肤**：按正版 ID 通过 Mojang 官方接口查询并下载皮肤（请求签名版本，所以第二层皮肤——外套、袖子、裤腿、帽子——也会显示），宽臂/细臂自动匹配；默认皮肤来自作者 **ChinaEX123_BILI**。ID 输错会提示，网络异常会单独提示。
  - **离线也能用**：模组自带作者皮肤 `assets/player_partner/textures/entity/default_skin.png`。查询失败（断网、被限流、ID 不存在）时伙伴照常生成，客户端直接用这张内置皮肤渲染（宽臂模型），不会变成 Steve，也不会出现“召不出来”。
- **玩家式物品栏**：潜行 + 右键伙伴打开界面，包含 6 个装备槽（主手、副手、头盔、胸甲、护腿、靴子）+ 36 格玩家式背包（27 格储物 + 9 格快捷栏）。主手槽直接对应快捷栏当前选中的那一格，和玩家一致。
  - 护甲槽只接受对应部位的装备；主手/副手任意物品。
  - 界面里「物品栏」文字右侧那条浅色横条里显示三项数值，各是“图标 + `x数字`”：❤ 生命值、胸甲 护甲值、🍗 饥饿值。
  - 鼠标悬停在物品上会显示完整的物品提示（名字、附魔、耐久等），和箱子界面一致。
- **饥饿与进食**：伙伴有饥饿值、饱和度、疲劳度，饿了会自己把食物放到副手吃掉；优先吃没有负面效果的食物，只有背包里只剩腐肉这类食物时才会吃。它会像玩家一样因为活动而变饿：每走一格加 0.1 疲劳、每跳一次额外加 0.1，疲劳攒够 4 点扣一点饱和度或饥饿值（原版 1.21 里普通走路本身不加疲劳，只有疾跑和跳跃才加，而伙伴不会疾跑，所以这里按位移自己补算）。界面上的饥饿值走菜单数据同步，读的是伙伴服务端的真实值。
- **会被击退**：受到伤害后会“僵直” 0.5 秒（`STAGGER_TICKS = 10`），这段时间不接管移动；同时受击时会显式补一次水平冲量（0.35）并打上 `hurtMarked`，让服务器把速度包广播给客户端——假玩家没有客户端帮忙同步速度，只靠原版击退经常看不出位移。
- **像普通生物一样活动**：不会一直贴在玩家身边。平时按 75% 闲逛 / 25% 停下张望的节奏自己活动，玩家离得近时还有概率抬头看你两眼；走路时朝行进方向，闲站时每 2~5 秒左右张望。
- **走丢保护**：只有距离超过 **64 格**才会尝试走向玩家，一次尝试最多走 5 秒、中间冷却 2 秒，最多试 **3 次**；3 次都没走过去（中间隔着山、峡谷之类）就直接瞬移回玩家身边。回到 32 格以内会重置次数。
- **安全保护**：掉到虚空（低于世界最低高度 8 格）会立刻瞬移回玩家身边；走路前会检查前方 0.8 格、脚下 4 格内有没有实体方块，没有就换方向，避免自己从悬崖边掉下去。
- **开界面时站定**：有玩家打开伙伴的界面时它会停下不动（`menuViewers` 计数），界面关掉后立刻恢复闲逛/张望。抬头看完玩家之后再走路，头会自己摆正，不会一直仰着。界面左上角的标题显示的是**这个伙伴当前的名字**（改名后再打开就是新名字）。
- **看向玩家时会抬头**：伙伴眼睛高度约 0.81 格、玩家约 1.62 格，所以“看玩家”必然是抬头动作（俯仰角限制在 -30°~-4°，永不低头）。
- **不捡掉落物**：伙伴不会主动捡地上的东西（`Player.touch` 被拦截）。
- **受击才举盾**：伙伴被打时才防守——如果背包里有盾牌，会把副手的食物临时换成盾牌并举起来，正面伤害按原版 `isDamageSourceBlocked` 规则挡下（消耗盾牌耐久、挡下后击退攻击者，都是原版行为）。防守持续 5 秒、期间再被打就重新计时；连续 2 秒没有威胁就提前收盾，盾牌放回原来那一格、食物放回副手，饥饿时继续照常吃东西。举盾时会面朝威胁方向并站着不动。
- **持久化**：伙伴会记录在存档的 `player_partners.json` 里，服务器重启后自动恢复；死亡后不会无限重生（只掉落物品、记录被移除）。
- **不挡睡觉**：伙伴是真正的玩家实体，但不会上床。旧的 `SleepStatus` 会把它算进“在线玩家”，导致 `playersSleepingPercentage`（默认 100%）永远凑不齐、玩家躺下就到不了天亮；模组用 mixin 把伙伴从这项统计里排除，睡觉只按真实玩家算。
- **数量上限**：通用配置 `partnerLimit`（默认 1），限制同时存在的伙伴数量；读档时也会裁剪超出的记录。

## 任务（界面左侧按钮）

伙伴界面左边有 4 个任务小按钮，界面的**右边**还有一个漏斗按钮（打开“任务过滤”，按任务类型分页设置各自的过滤，见下一节），点一下任务按钮就让这个伙伴去干对应的活，再点同一个按钮就收工（回到自己闲逛）。

按钮底是三张 **20 × 20** 的小图：`job_button.png`（普通）、`job_button_hover.png`（鼠标悬停）、`job_button_selected.png`（当前正在干这个活），代码按“悬停 > 选中 > 普通”的优先级挑一张贴上去（显式传了贴图尺寸，所以画多大都行，不用凑 256×256）。按钮上的图标不在贴图里，是代码里直接渲染的物品——剑、镐、斧、锄（想换图标改 `PlayerPartnerScreen.JOB_BUTTON_ITEMS` 就行）。鼠标悬停还会显示任务名和一句说明。

- **战斗**（剑）：跟着主人打敌对生物，优先打主人正在打的那只（读主人的 `getLastHurtMob()`），其次打附近盯上主人或自己的怪；够不到就走过去，够得到就每 1 秒挥一次。
- **挖矿**（镐）：在附近找可挖的方块走过去挖掉，掉落物直接塞进伙伴背包，塞不下才掉在地上。挖什么方块由**伙伴界面里漏斗按钮打开的白名单/黑名单**决定（也支持 `/playerpartner mining ...` 指令），默认白名单 `#c:ores`（所有矿石），黑名单优先。
- **砍树**（斧）：找附近的原木（`#minecraft:logs`）砍掉，砍完继续找下一块，一棵树会从上往下被砍干净，木头同样进背包。
- **耕种**（锄）：手上拿着锄头时会找泥土/草方块锄成耕地；背包里有作物种子（小麦、胡萝卜、马铃薯、甜菜根等）时会先找空耕地种下去，没种子才锄地。

任务期间伙伴受击照样会举盾防守、饿了照样会吃东西，这两个优先级比干活高。干活时会播放对应动作：打怪挥剑，挖矿/砍树每 6 tick 挥一次手，锄地、播种各挥一次（假玩家没有客户端输入，所以是代码主动调 `swing()` 让服务端广播动画包）。

指派的任务会记进存档的 `player_partners.json`（每条记录一个 `job` 字段），服务器重启或伙伴被重新加载后会接着干上次的活；老存档没有这个字段时按“无任务”处理。

## 使用

```bash
/playerpartner spawn              # 召唤默认伙伴：名字 PlayerPartner，皮肤 ChinaEX123_BILI
/playerpartner spawn Notch        # 指定皮肤来源的正版 ID
/playerpartner rename <名字>       # 重命名附近的伙伴（会以新名字重新生成）
/playerpartner remove             # 移除附近的伙伴
/playerpartner open               # 打开附近伙伴的物品栏（需要 OP，方便测试）
/playerpartner list               # 列出当前所有伙伴
```

也可以直接用物品召唤：

- **玩家伙伴刷怪蛋**：按原版刷怪蛋的方式注册，外观与普通刷怪蛋一致，用掉一个。
- **玩家伙伴召唤物**：单独的物品，自定义图标，用掉一个。

### 用命名牌改名字／换皮肤

拿着写好的命名牌**对着伙伴右键**即可（不用潜行，潜行是开物品栏）：

- 命名牌上的文字会被当作 **正版 ID**：查到该账号就改名为它，并把皮肤换成该账号的皮肤（第二层皮肤也会一起更新）。
- 如果你写的是普通名字（不是一个真实的正版 ID），会提示“找不到该正版账号”，伙伴保持原样，不会消失也不会丢东西。
- 改名过程中伙伴背包里的物品会先被暂存、改完再放回去，不会掉出来。

## 自定义界面贴图

贴图：`assets/player_partner/textures/gui/player_partner.png`，画布 **256 × 256**，游戏内容只占左上角 **178 × 222**，其余透明。这里之所以要 256×256，是因为面板用的是不带尺寸参数的 `blit`，它固定按 256×256 取样；如果像按钮那样显式传入贴图尺寸（`blit(tex, x, y, u, v, w, h, texWidth, texHeight)`），画布就可以随便多大，`job_button*.png` 这三张就只有 20×20。

当前用的是深色风格：底板蓝灰渐变 `(158,163,184) → (145,151,174)`，1px 黑描边 + 1px 亮边 + 3px 圆角；槽位是更深的藏青 `(60,62,84)`，左上带 1px 高光 `(104,108,128)`、右下 1px 暗边 `(38,39,55)`，四角 1px 圆角。文字（标题与「物品栏」）在代码里用浅色 `0xE6E8F2` 绘制，因为原版默认的深灰字在深色底板上看不清。

槽位都画在贴图里，图标和文字由代码叠加。下面所有坐标都是槽位左上角（相对面板左上角），槽位本身 18×18，网格按 18 递增：

- **装备槽（主手、副手）**：2 个，`y = 19`，`x = 9`（主手）和 `27`（副手）。
- **装备槽（头盔、胸甲、护腿、靴子）**：4 个，`y = 19`，`x = 63 / 81 / 99 / 117`，和主副手之间空一格。
- **伙伴背包（3 排主背包）**：27 个，`x = 9 + 列*18`，`y = 41 / 59 / 77`。
- **伙伴快捷栏**：9 个，`x = 9 + 列*18`，`y = 99`，与上方主背包空开 4 像素。
- **三项数值**（代码绘制，每组是“一个图标 + `x数字`”）：3 组 9×9 图标，`y = 122`，饥饿 `x = 48`、护甲 `x = 82`、生命 `x = 118`，数字在图标右侧 11 像素处，画在贴图那条浅色横条里。
- **「物品栏」文字**：`(9, 124)`。
- **玩家背包**：27 个，`x = 9 + 列*18`，`y = 139 / 157 / 175`。
- **玩家快捷栏**：9 个，`x = 9 + 列*18`，`y = 197`。

## 任务过滤（界面里设置）

伙伴界面**右边**有一个漏斗按钮（和左侧的任务按钮同尺寸，贴在面板右边缘外面），点开就是**任务过滤**界面，不用改配置文件、也不用记指令。界面顶部按任务类型分页（战斗 / 挖矿 / 砍树 / 耕种），分别在各自页面里设置过滤规则；目前只有“挖矿”有可设置的项，其它任务先显示“该任务暂时没有可过滤的项”，以后加过滤只需往对应页里填内容。

规则存在存档里（`player_partner_mining` 这份存档数据），改完立刻生效，伙伴下一 tick 就按新规则找方块，重启后还在。

界面里能做的事：

- 顶部按钮切换**白名单 / 黑名单**。白名单＝只挖列表里的方块；黑名单＝列表里的不挖（两边都命中时黑名单优先）。
- 输入框里填方块 ID 或标签，回车或点「添加」加入列表。标签要带 `#` 前缀（例如 `#c:ores` 表示所有矿石标签），单方块直接写 `minecraft:iron_ore`。
- 每条右边有个 `x`，点一下就从列表里删掉；「清空」清空整个列表。
- 白名单模式下列表为空时视为什么都能挖，避免设错之后伙伴彻底不干活。

规则是整个世界共用的，所以改动需要 OP 权限（和 `/playerpartner ...` 一样）。指令版仍然保留，不想开界面的人可以直接用：

```
/playerpartner mining mode whitelist      # 白名单：只挖列表里的方块
/playerpartner mining mode blacklist      # 黑名单：列表里的方块不挖（黑名单优先）
/playerpartner mining add minecraft:iron_ore
/playerpartner mining add #c:ores         # 整类方块用标签，带 # 前缀
/playerpartner mining remove #c:ores
/playerpartner mining list                # 看当前模式与列表
/playerpartner mining clear               # 清空列表
```

## 配置

`config/player_partner-common.toml`：

```toml
# 同时存在的伙伴数量上限（默认 1）
partnerLimit = 1

[jobs]
# 接活时搜索目标的半径（格）
jobRadius = 8
# 新建世界时挖矿过滤的初始白名单（之后以游戏内指令改的规则为准）
miningWhitelist = ["#c:ores"]
# 新建世界时挖矿过滤的初始黑名单
miningBlacklist = []
```

`miningWhitelist` / `miningBlacklist` 只在存档里还没有挖矿规则时用作初始值（默认白名单 `#c:ores`），之后一律以游戏内界面（或 `/playerpartner mining` 指令）设置的规则为准——改配置文件不会覆盖已有存档的规则。

## 构建

需要 JDK 21：

```bash
gradlew.bat build
```

产物在 `build/libs/player_partner-1.0.0-mc1.21.1-neoforge.jar`。

## 注意

- 皮肤依赖 Mojang 官方接口，需要能访问 `api.minecraftservices.com` 与 `sessionserver.mojang.com`。
- 伙伴是服务端实体，服务端和客户端都要安装本模组。
